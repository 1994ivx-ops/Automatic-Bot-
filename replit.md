# Telegram + Browser Automation Bot

A dual-bot Telegram automation system. The **userbot** (Telethon) iterates tasks, clicks inline buttons, injects referral tokens, and triggers Playwright browser visits. The **control bot** (token-based) lets the owner start/stop/monitor from Telegram. A lightweight Flask server keeps Railway's port health-check happy.

## Run & Operate

- `python main.py`         — normal run (control bot + Flask health server)
- `python main.py auth`    — first-time interactive auth (run locally, see below)
- `bash setup.sh`          — install Python deps + Playwright Chromium (Railway build cmd)

## First-Time Userbot Auth (required before Railway deploy)

Railway has an ephemeral filesystem and no interactive TTY. The session must be
generated locally, then stored as an environment variable.

1. Set all required env vars locally (or fill `config.json`):
   `API_ID`, `API_HASH`, `CONTROL_BOT_TOKEN`, `PERSONAL_TELEGRAM_ID`,
   `PROXY_HOST`, `PROXY_PORT`, `PROXY_USERNAME`, `PROXY_PASSWORD`

2. Run the interactive auth:
   ```
   python main.py auth
   ```
   Telethon will ask for your phone number → OTP code → (optional) 2FA password.

3. After success the script prints a **SESSION_STRING** value.
   Copy that entire string.

4. In your Railway project → **Variables**, add:
   ```
   SESSION_STRING = <paste the string here>
   ```

5. Redeploy the Railway service. The Control Bot will message you on Telegram
   with "🤖 Control Bot is online and ready!" once it's up.

## Required env vars (Railway Variables)

| Variable              | Notes                                  |
|-----------------------|----------------------------------------|
| `API_ID`              | Telegram app API ID (my.telegram.org)  |
| `API_HASH`            | Telegram app API hash                  |
| `CONTROL_BOT_TOKEN`   | BotFather token for the control bot    |
| `PERSONAL_TELEGRAM_ID`| Your Telegram user ID (integer)        |
| `PROXY_HOST`          | SOCKS5 proxy hostname (or host:port)   |
| `PROXY_PORT`          | SOCKS5 proxy port                      |
| `PROXY_USERNAME`      | Proxy username                         |
| `PROXY_PASSWORD`      | Proxy password                         |
| `SESSION_STRING`      | Generated by `python main.py auth`     |
| `PORT`                | Set by Railway automatically           |

## Stack

- Python 3, Telethon, Playwright, Flask
- Railway for hosting (Procfile: `web: python main.py`)
- SOCKS5 proxy for all Telegram + browser traffic

## Where things live

- `main.py`       — all bot logic (userbot cycle, control bot, Flask health)
- `targets.json`  — list of Telegram bot tasks (bot username, buttons, referral)
- `config.json`   — local dev fallback config (ignored in prod, gitignored)
- `setup.sh`      — Railway build command (pip + Playwright install)
- `Procfile`      — Railway start command

## Architecture decisions

- `StringSession` env var (`SESSION_STRING`) is used on Railway; file-based session
  is used locally. `_get_userbot_session()` in `main.py` selects automatically.
- `targets.json` is written with an atomic rename to prevent corruption if the
  process is killed mid-write.
- Flask runs on a daemon thread so Railway's port health-check passes without
  blocking the asyncio event loop.
- The control bot session uses bot_token auth (non-interactive, re-authenticates
  automatically on each start) so it does not need a StringSession.

## Gotchas

- If the session is revoked (e.g. you log out from all devices in Telegram), you
  must re-run `python main.py auth` locally and update `SESSION_STRING` on Railway.
- Never commit `*.session` files or `SESSION_STRING` values — they grant full
  account access. Both are gitignored.
- Playwright Chromium must be downloaded during build (`bash setup.sh`) — it is
  not in the repo.
